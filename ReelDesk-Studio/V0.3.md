# ReelDesk Studio v0.3.0 — transitions and audio

This incremental release follows the locked Transitions & Audio milestone and builds on the tested v0.2 source. The feature PR targets the v0.2 branch because the earlier import/timeline PRs are still pending. No earlier PR is merged by this change.

## Editing workflow

1. Import and arrange videos or photographs as before.
2. Select a clip and scroll the right inspector to **Transition to next clip**. Choose Crossfade, Dissolve, Slide left/right, Wipe, Zoom, Fade through black, or Flash. Cut remains the default.
3. Set transition duration from 0.05 to 5 seconds. The effective overlap is limited to half of each adjacent clip and rounded down to a 30 fps frame. The inspector displays the effective value; the timeline overlaps clip blocks and shows a transition badge. A transition on the last clip has no effect until a following clip exists.
4. Set a video's volume (0–200%) and audio fade in/out. A volume of zero mutes it. Fade durations are in output seconds after playback speed, capped to half the clip length. Image clips contribute silence.
5. Keep the existing background soundtrack, now with fade in/out, or use **+ Music / voiceover track** for up to eight additional imported audio tracks. Each track has a timeline start, source start/end, gain, fades, and optional looping of its trimmed section. Audio lanes show their placement. Remove and undo work for tracks too. Voiceovers are imported recordings; microphone recording is not included.
6. Click **Preview sequence** to render a 720p preview using the same FFmpeg graph as export. It plays the complete sequence with transitions and the audio mix through native playback controls. **Back to clip** returns to immediate selected-clip editing. Any edit invalidates a displayed preview; edits during rendering require rendering again. Cancel uses the existing render cancellation control.
7. Save the editable project or export the MP4. Export quality still uses your selected 720p/1080p/2160p setting; rendering a preview does not change it.

## Timing and compatibility

Transitions overlap footage, so they shorten the final sequence. For example, two 2-second clips with a 0.5-second crossfade produce a 3.5-second video. Timeline duration, clip start labels, title preview time, and FFmpeg export share the same overlap model. Original clip audio crossfades over the same interval. Splitting puts the outgoing transition on the right-hand segment; the new internal boundary starts as a cut.

Additional tracks are mixed at their specified timeline offsets. Nonlooping tracks end after their trimmed source section. Looping tracks repeat that section until the sequence ends. Tracks starting beyond the sequence remain editable but are inaudible in that export. Fades apply over the audible part of a track, including its repeated section. The mix uses a peak limiter without automatic gain normalization or added limiter delay. These are editing controls, not loudness mastering.

New saves use project version 3 and retain transitions, clip audio settings, soundtrack fades, and audio tracks. Version 1 and 2 projects still load with cuts, full original clip volume, and zero fades. Use v0.3 to edit v3 projects: older application versions do not understand all of these fields. Source files must stay available on disk. Source media remains unmodified.

## Running and testing

Use the same setup as v0.2: `npm install`, then `npm start` from this directory, with FFmpeg and FFprobe installed. The selected FFmpeg build needs `xfade`, `acrossfade`, `afade`, `aloop`, `adelay`, and `amix`; integration tests exercise the transition filters in the installed binary. Text overlays still require `drawtext`, which is absent from the FFmpeg build on this test Mac. A title is not silently omitted from a render; a missing filter produces a render error.

The final macOS verification run passed 16 tests, with one title-render test skipped for the missing `drawtext` filter.

`npm test` includes the existing v0.2 regressions plus overlap/split tests, all eight transition renders, decoded frame checks for crossfade blending and clip order, delayed/trimmed/looping audio sample checks, gain/fade/mute checks on speed-adjusted videos, save/load compatibility, and cancellation/source-preservation checks. FFmpeg integration tests skip when the tools are unavailable.

The optional Playwright runner instructions in V0.2.md still apply. Browser automation exercises transition settings, overlap duration, track settings, preview mode, undo/redo, splitting, reordering, and trimming. With `ELECTRON_PATH` configured, the desktop test imports real images/audio, renders a transition preview, verifies its duration, saves v3, and reopens it with tracks intact.

## Remaining work

- This release has eight transition styles with linear/default FFmpeg behavior. Custom easing, blur/spin transitions, and a larger preset library remain future increments.
- Immediate clip preview shows a single source clip. It respects volume up to the browser's 100% ceiling; fades, amplified gain, overlapping transitions, and the full mix are auditioned through the rendered sequence preview. Preview generation can take time for long projects.
- Audio placement and trims use numeric controls. Waveforms, draggable audio edges, automation envelopes, ducking, and in-app microphone recording are not included.
- Looping buffers a trimmed audio section in FFmpeg; long trimmed sections and many simultaneous tracks need performance profiling. Prefer short loop sections on memory-constrained machines.
- The two latest successful preview renders are retained in temporary storage and removed on normal exit. Failed/cancelled previews are removed. Crash cleanup and render queueing remain future work.
- v0.2's HEIC camera-sample validation, independent image position/scale/crop, and installer signing/distribution remain incomplete. No transitions or audio feature here changes those outstanding items.
